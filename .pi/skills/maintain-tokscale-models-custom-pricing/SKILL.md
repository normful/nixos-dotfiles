> **Document status:** Active
> **Authoritative file:** `chezmoi/dot_config/tokscale/custom-pricing.json` (chezmoi source; installs to `~/.config/tokscale/custom-pricing.json`)

## Tokscale upstream rules (README, re-read 2026-09-05)

Source: `https://raw.githubusercontent.com/junhoyeo/tokscale/refs/heads/main/README.md`
(`Custom Pricing Overrides` + `Unpriced usage is excluded from submission` sections).
These override older skill assumptions where they conflict.

- **Lookup order (8 steps):** 1. custom overrides → 2. exact match (LiteLLM/OpenRouter) →
  3. alias resolution → 4. tier-suffix stripping → 5. version normalization →
  6. provider-prefix matching → 7. hardcoded Cursor pricing → 8. fuzzy matching.
  `tokscale pricing <model-id>` prints which step matched (e.g. `Resolution: fuzzy
  (estimate only, N candidates)`). **But: a fuzzy/provider-scoped match shown by
  `pricing` does NOT satisfy submit** — verified 2026-09-05: `pricing` showed
  fuzzy estimates for `MiniMaxAI/MiniMax-M3` and `inclusionai/ling-3.0-flash`
  while submit still warned on both. Only step 1 (exact custom entry) counts.
- **Key = model half only:** file is keyed by the `model` half of the submit
  warning's `provider/model` pair — slashes included. One key covers every
  provider/client using that model half (`hermes/` + `nous/` + `openrouter/`
  `poolside/laguna-s-2.1:free` = single key `poolside/laguna-s-2.1:free`).
  Exact-only and case-insensitive: `minimax-m3` does NOT cover `MiniMaxAI/MiniMax-M3`.
- **All six submit exclusion reasons** (skill previously knew only the bucket one):
  1. `no authoritative model-to-price mapping` — absent everywhere;
  2. `generic routing label has no authoritative model-to-price mapping` — router
     labels (`auto`, …); explicit custom entry is the supported assert-a-rate fix;
  3. `pricing does not cover every populated token bucket` — missing cache rate
     (fixed via `backfill_buckets`);
  4. `model price match does not establish the requested provider` — model-part
     or prefix match only, provider billing unproven;
  5. `model price match does not exactly name the requested model` — fuzzy match only;
  6. `model price lookup is ambiguous across non-equivalent candidates` — several
     rows, different prices.
- **Explicit 0 vs omitted:** explicit `0` = "this costs nothing" (free declaration);
  omitted field = unknown → unpriced. Never omit to mean free.
- **Schema extras:** LiteLLM per-token names accepted but per-million recommended;
  optional `source`/`notes` ignored by tokscale (bookkeeping only);
  negative/non-finite values skip the whole entry; overrides load once at startup
  (restart command after editing).
- **Observed submit behavior (binary newer than README):** README says unpriced is
  `excluded`; the installed binary instead **submits unpriced usage at $0.00 with
  days marked cost-incomplete** so it cannot lower recorded spend, plus the Hint
  to add exact-match entries keyed by the model half and re-check with
  `tokscale submit --dry-run` + `tokscale pricing <model-id>`.
- **Verification workflow (docs):** re-run `tokscale submit --dry-run` until no
  warnings remain; `tokscale pricing <model-id>` shows which entry matched.
  The dry-run warning list (all clients) is therefore a second driver alongside
  pi-session extraction — it catches slash-form model halves no alias rule covers.
- **Out of scope for this skill:** `tokscale cursor login` + `tokscale cursor sync
  --json` (Cursor cache prerequisite) and `tokscale hindsight sync` (Hindsight
  ledger prerequisite). Those warnings are setup steps, not pricing.

## Process

Single script does it all — `scripts/maintain.py` replaces 9 previous scripts:

```
python3 scripts/maintain.py                 # full run (cached /tmp catalog if present)
python3 scripts/maintain.py --fetch         # force re-fetch https://aihubmix.com/api/v1/models
python3 scripts/maintain.py --dry-run       # build to /tmp/custom-pricing.new.json only, don't overwrite chezmoi
python3 scripts/maintain.py --check         # validate current chezmoi file vs full catalog
python3 scripts/maintain.py --extract       # force re-extract sessions (otherwise use cached /tmp/provider_map.json)
```

What the single script does internally (in order):
1. `fetch_catalog()` — `curl -s https://aihubmix.com/api/v1/models` → `/tmp/aihubmix_models_all.json` (and `?type=llm` for reference), `jq '.data | length'` to verify.
2. `extract_sessions()` — rglob `~/.pi/agent/sessions/**/*.jsonl`, `json.loads` per line + regex fallback, collects unique + provider map → writes `/tmp/unique_model_ids.json` + `/tmp/provider_map.json`.
3. `build()` — filters strict `aihubmix*` (skips `cheap`/`crush-*`), resolves alias → catalog ID via `ALIAS_MAP` + generic `-deepseek-v4-flash` rule, `to_tokscale()` maps `input/output/cache_read/cache_write` → `input_cost.../output.../cache_read.../cache_creation...`, then `backfill_buckets()` adds explicit `0` for session-populated cache buckets missing a rate (source: `/tmp/tokscale_models.json` via `load_session_buckets()`); non-aihubmix IDs in `MODELS_DEV_MAP` priced from models.dev (`load_models_dev_costs()`); `PINNED_RATES` model-half keys and `:free`-suffixed IDs (explicit 0) applied to any used ID; `FREE_IDS` forced 0/0/0; adds explicit free `big-pickle`/`solar-pro4:free` (0/0/0), writes sorted `chezmoi/dot_config/tokscale/custom-pricing.json` (no `.bak` — pre-run HEAD is the rollback; never commit, see Commit policy), syncs `~/.config` + `/tmp/custom-pricing.new.json`, `jq .` validation.
4. `check()` — validates current file vs full catalog + `MODELS_DEV_MAP` + `PINNED_RATES` + same bucket backfill (the skipped `cheap`/`crush-*` + `@preset/*` are intentionally absent).

Manual `jq` checks still useful for gigantic file:
```bash
jq '.data | length' /tmp/aihubmix_models_all.json
jq -r '.data[].model_id' /tmp/aihubmix_models_all.json | grep -i "<id>"
jq '.models | length' chezmoi/dot_config/tokscale/custom-pricing.json
jq '.models["cc-k2.6-code-preview"]' chezmoi/dot_config/tokscale/custom-pricing.json
```

## Commit policy (standing rule, 2026-09-05)

- **Skill runs never commit, never branch.** `main` is a protected branch and
  agents cannot commit to it. Routine pricing runs leave all changes
  uncommitted in the working tree; the run report ends with `git diff --stat`.
- **Rollback = pre-run HEAD.** Overwriting the chezmoi source is safe without a
  commit because the last committed state restores via `git checkout -- <file>`.
  No `.bak` files, ever.
- **Norman commits on review.** A commit happens only on Norman's explicit
  instruction (e.g. "commit this"), never implied by "apply" or "run".
  Branching per pricing run is noise — don't.

## Maintenance Rules

- Always `curl` the **full** models endpoint (no `?type=llm`) for pricing; `?type=llm` misses `cc-k2.6-code-preview` and other code-type models.
- Use `jq` selectively (`select(.model_id=="...")`) — never dump the whole catalog file.
- Keep keys sorted alphabetically in `custom-pricing.json`.
- Keep `cache_creation` alongside `cache_read` where `cache_write` exists.
- For any new `<prefix>-deepseek-v4-flash` alias, map to `deepseek-v4-flash-0731`.
- For any new unknown alias: preset/router labels (`@preset/*`) stay out (accepted loss); anything else gets a researched `PINNED_RATES` entry or stays out with candidates noted — proceed with a documented default, don't pause for questions on routine runs.
- Directly overwrite `chezmoi/dot_config/tokscale/custom-pricing.json` (no `.bak` files — pre-run HEAD is the rollback); `~/.config/tokscale/custom-pricing.json` is then derived via `chezmoi apply` or manual copy. See Commit policy — never commit from a skill run.
- `big-pickle` and `solar-pro4:free` are intentional free entries not in aihubmix catalog — keep them.
- Key new submit-warning IDs by the **model half** (slashes included), never the
  `provider/model` pair — one key covers all providers/clients on that model.
- Any used ID ending `:free` → explicit 0/0/0 via the generic rule; never omit fields to mean free.
- Paid additions go in `PINNED_RATES` with a `source` comment, priced from the provider Norman pays (pi `models.json` cost block > provider's own page > OpenRouter/models.dev). Cross-check two sources when spend is material.
- Never assert a rate from a sibling model (`laguna-xs-2.1` ≠ `laguna-xs.2`); a weakly-sourced default is allowed only on Norman's explicit "include", recorded with its source and a flip note — otherwise leave pending with candidates noted.
- Preset/router labels (`@preset/*`) with unknown rates stay out (accepted loss, `@preset/glm47` precedent) — an explicit entry is only added when Norman knows the rate.
- After each run, verify with `tokscale submit --dry-run` (goal: no warnings) and `tokscale pricing <model-id>` (must show the custom entry, not a fuzzy estimate).

## Common Mistakes to Avoid

1. **Using `?type=llm` only** — misses code models; always fetch full catalog.
2. **Mapping `cc-k2.6-code-preview` to `kimi-k2.6`** — wrong (0.95 vs 0.2); use direct `cc-k2.6-code-preview` (0.2/0.2/0.02).
3. **Ignoring `cache_write`** — must map to `cache_creation_input_token_cost_per_million_tokens`.
4. **Normalizing keys** — keep exact session string (`deep-deepseek-v4-flash`), don't replace with canonical.
5. **Assuming a bare key covers slash-form model halves** — `minimax-m3` does NOT cover `MiniMaxAI/MiniMax-M3`, and `ling-3.0-flash-free` does NOT cover `inclusionai/ling-3.0-flash:free`. Submit matches the full model half exactly; each slash form needs its own key.
6. **Over-broad scope** — the aihubmix path stays strict-`aihubmix*` (provider actually used); non-aihubmix IDs enter only via `MODELS_DEV_MAP`/`PINNED_RATES`/`:free` rule.
7. **Forgetting free 0 entries** — `big-pickle`/`solar-pro4:free` and other `*-free` should stay 0/0/0.
8. **Creating `.bak` files** — never write backup files; pre-run HEAD is the rollback (see Commit policy).
